Visibility becomes momentum

Your agents are parallel.
Your visibility should be too.

Claude Sessions turns the transcripts Claude Code already writes into an actionable operations layer. No proprietary database, no heavyweight web stack, no changes to your existing workflow.

01 / LIVE OVERVIEW

Know what needs you now.

Working, idle, and stale states; pending approvals; unread replies; project grouping; search and filters. The next action is always visible.

02 / FULL CONTEXT

More than a status light.

Read Markdown conversations, inspect tool results and diffs, follow tasks and subagents, and compare model, branch, and token usage.

03 / HOSTED SESSIONS

Keep the conversation alive.

A persistent stream-json process brings streaming replies, queued follow-ups, model and effort controls, slash-command hints, and interruption.

04 / HUMAN CONTROL

Automation with a brake pedal.

Handle tool permissions and AskUserQuestion prompts in the browser. Choose ask, auto, or full approval per hosted session—and interrupt when priorities change. While the tab is hidden, browser notifications flag new replies, approvals, and failures.

05 / BUILT FOR HISTORY

Large transcripts stay manageable.

Incremental JSONL parsing, validated restart caches, lazy subagent loading, and paginated message windows keep long histories responsive.

From clone to control in minutes

Start with three commands.

You need Python 3.9+, uv, and—only for messaging or hosting—an installed and configured Claude Code CLI. Monitoring existing transcripts works without starting Claude.

Clone the repository

Get the service, dashboard, tests, and documentation.

$ git clone https://github.com/ciknight/cc-session.git
$ cd cc-session

Install dependencies

Let uv resolve the small Python dependency set.

$ uv sync

Open your dashboard

Start locally, then visit http://127.0.0.1:8765.

$ uv run monitor.py --host 127.0.0.1

Read before exposing the port

Powerful controls.
Trusted networks only.

Claude Sessions is intentionally lightweight and has no authentication. Treat it as a local operations tool, not a public multi-user service.

  • Bind to localhost by choice.Use --host 127.0.0.1. The default 0.0.0.0 listens on every interface.
  • Know the default approval mode.Hosted sessions default to full, which automatically approves permission requests. Choose ask for human review.
  • Protect the machine behind it.Messaging can run Claude with your local permissions; system controls can sleep or restart the host.
  • A browser prompt is not authorization.Do not expose the service publicly without adding proper authentication, authorization, TLS, and request protections.
