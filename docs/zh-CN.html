Claude Sessions 把 Claude Code 已经写入的转录变成可执行的操作层。不需要专有数据库，不引入重量级 Web 框架，也不要求改变原有工作流。

01 / 实时概览

现在哪里需要你，一眼就知道。

工作中、空闲和 stale 状态，待审批、新回复、项目分组、搜索与筛选，让下一步行动始终清晰可见。

● 工作中◌ 空闲◇ stale! 审批
02 / 完整上下文

不只是一个状态灯。

阅读 Markdown 对话，检查工具结果和 diff，跟踪任务与子代理，并查看模型、分支和 token 用量。

03 / 托管会话

让对话持续在线。

常驻 stream-json 进程带来流式回复、追问排队、模型与思考档位控制、斜杠命令提示和中断能力。

04 / 人工控制

自动化，也保留刹车。

在浏览器中处理工具权限和 AskUserQuestion 提问。每个托管会话可选择 ask、auto 或 full，并能随时中断当前回合。页面隐藏时，新回复、待审批与失败还会通过浏览器通知提醒你。

05 / 面向长历史

再长的转录，也易于管理。

增量 JSONL 解析、带校验的重启缓存、子代理懒加载和消息分页，让大型历史记录依然保持响应速度。

06 / 开放设计

看板只是起点。

基于同一套 JSON API、SSE 事件流和可选 webhook，构建通知、脚本或完全不同的客户端。

几分钟，从克隆到掌控

三条命令即可开始。

你需要 Python 3.9+ 和 uv；只有发送消息或托管会话时，才需要安装并配置 Claude Code CLI。监控已有转录不需要启动 Claude。

克隆仓库

获取服务、看板、测试和完整文档。

$ git clone https://github.com/ciknight/cc-session.git
$ cd cc-session

安装依赖

让 uv 安装项目少量的 Python 依赖。

$ uv sync

打开看板

在本机启动，然后访问 http://127.0.0.1:8765。

$ uv run monitor.py --host 127.0.0.1

控制能力强。
仅限可信网络。

Claude Sessions 刻意保持轻量，不提供身份认证。请把它当作本地操作工具，而不是公网多用户服务。

  • 主动选择只监听本机。使用 --host 127.0.0.1。默认的 0.0.0.0 会监听所有网卡。
  • 了解默认审批模式。托管会话默认使用 full，会自动批准权限请求。需要人工审查时请选择 ask。
  • 保护服务所在的机器。发消息会以你的本地权限运行 Claude；系统控制可以让宿主机睡眠或重启。
  • 浏览器确认不等于授权。如需对外开放，必须自行添加身份认证、授权、TLS 和请求防护。
