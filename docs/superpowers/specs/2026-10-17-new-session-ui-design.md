# 设计：看板"新建会话"入口

日期：2026-10-17
状态：已批准

## 背景

`POST /hosted` 传 `{"cwd": "<目录>", "text": "<首条消息>"}`（不带 `resume_id`）即可在指定
目录托管启动一个全新会话（`Hosted.start` 不加 `--resume`，`_on_init` 从 init 事件拿到新
session id）。后端能力已完整，仅缺看板 UI 入口。

## 目标

在看板上为任意项目直接创建全新会话并发送首条消息，不依赖已有会话历史。

## 方案

改动范围仅 `templates/index.html`，零后端改动。

### 入口

- 侧边栏每个项目条目（`pitem`）右侧加 `+` 按钮；
- 右侧会话列表页的项目标题旁加"新建会话"按钮。

点击后 `view = {project: cwd, session: null, new: true}`，右侧切换到空白新会话视图。

### 空白新会话视图

复用现有消息发送框样式，顶部显示"将在 `<项目路径>` 新建会话"提示 + 返回按钮；
只有消息输入框 + 发送按钮——没有"托管"和"force"勾选框（新会话必须走托管常驻进程；
首轮跑完自动进入正常会话，之后可随时"退出托管"，与现有会话流程一致）。

### 发送与切换逻辑

```
点击发送 → POST /hosted {cwd, text}   → 返回 {hosted_id, job_id}
         → 并行轮询：
           a. GET /jobs/<job_id>     → 跟踪首轮状态（复用现有 sendJob 状态展示）
           b. GET /hosted            → 按 hosted_id 找 session_id
                                       （init 事件几秒内就到，不用等首轮跑完）
         → 拿到 session_id 后 view.session = sid 切到对话视图
```

新会话转录文件照常写入 `~/.claude/projects`，轮询线程自动发现，对话内容随后自然填充。

### 错误处理

- 后端校验 cwd 不存在 → 400，`error` 显示在状态行；
- claude 启动失败 → `/hosted` 列表里该项 `status: "exited"` + `stderr_tail`，在状态行展示；
- 输入为空不发送；重复点击创建不做限制（与现有 `/hosted` 行为一致，每次独立进程）。

## 测试

手动验证：对现有项目点新建 → 发首条消息 → 自动切到新会话对话 → 再发一条走常驻进程 →
退出托管后还能用一次性消息。
